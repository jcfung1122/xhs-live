# 7维达人筛选标准

> **权威版本 v2.0**  
> 此文档为筛选标准的唯一权威来源。脚本逻辑必须与此文档保持一致。
> 文中的「{用户品类}」指安装用户通过 `init_skill.py` 配置的主营品类（`config.json` 的 `brand.category`）。

## 一、基础筛选（搜索后立即执行）

基础筛选不通过 = 不入库，直接丢弃。

| # | 维度 | 规则 | 阈值 |
|---|------|------|------|
| 1 | 粉丝数 | ≥ | 50,000 |
| 2 | 场均观看 | ≥ | 5,000 |
| 3 | 场均销售额 | ≥ | 10,000 元（即 1 万） |

## 二、7维指标筛选（入库后执行）

数据来源：蒲公英千帆 API `get_user_detail` 接口。  
API 无数据（达人未开播过）→ 指标留空，评语也为空，等待后续补全。

### 2.1 四个指标

| # | 指标 | API 字段 | 含义 |
|---|------|----------|------|
| 4 | 活跃粉丝率 | `proportion_of_active_fans` | 粉丝中有多少是活跃用户 |
| 5 | 下单粉丝率 | `proportion_of_order_fans` | 粉丝中有多少下过单 |
| 6 | 客单价 | `fan_unit_price` | 每个下单粉丝平均消费金额（元） |
| 7 | GPM | `live_gpm` | 每千次观看产生的成交额（元） |

### 2.2 判定标准

| 指标 | 判定逻辑 | 不通过标记 |
|------|----------|------------|
| 活跃粉丝率 | < 50% | 「活跃粉丝率低」 |
| 下单粉丝率 | < 20% | 「下单率低」 |
| 客单价 | < 500 元 | 「客单价偏低」 |
| 客单价 | > 5,000 元，且**不满足豁免条件** | 「客单价偏高」 |
| GPM | < 3,000 | 「GPM低」 |

**评语生成规则**：
- 全部通过 → `✅ 优质`
- 有一项不通过 → 拼接该维度标记，多个用「；」分隔
  - 例：`活跃粉丝率低；GPM低`
  - 例：`客单价偏高`

## 三、客单价豁免规则

> 这是最重要的特殊规则，用于防止「误杀」实际价格带匹配的达人。

### 3.1 触发条件

客单价 > 5,000 元时，**不直接判定为不通过**，先检查豁免条件。

### 3.2 豁免条件

查看达人带货品类中的**实际价格带**（来自 `cooperation_category` 字段，格式为「价格带:XXX-XXX元」）。

| 条件 | 结果 |
|------|------|
| 价格带与 **500 ~ 2,000 元**有交集 | ✅ 豁免，不标记「客单价偏高」 |
| 价格带与 500~2000 无交集，或无价格带数据 | ❌ 不豁免，标记「客单价偏高」 |

### 3.3 为什么？

客单价是「粉丝人均消费」，不等于「达人卖的货的价位」。  
例子：示例达人 客单价 6,077（超标），但实际带货价格带 291~1,148 元，跟 你的品牌 包（768~1,099）完美匹配。如果不豁免就会错过。

### 3.4 豁免逻辑图示

```
客单价 > 5000?
  ├─ 否 → 正常判定（< 500 = 偏低，500~5000 = ✅）
  └─ 是 → 检查实际价格带
           ├─ 与 500~2000 有交集 → ✅ 豁免（不标记）
           └─ 无交集 / 无数据 → ❌ 「客单价偏高」
```

## 四、完整判定流程图

```
达人入库(PENDING)
    │
    ├─ API 有数据？
    │   ├─ 否 → 指标/评语留空，等待补全
    │   └─ 是 ↓
    │
    ├─ 活跃粉丝率 ≥ 50%？
    │   └─ 否 → +「活跃粉丝率低」
    │
    ├─ 下单粉丝率 ≥ 20%？
    │   └─ 否 → +「下单率低」
    │
    ├─ 客单价判定：
    │   ├─ < 500 → +「客单价偏低」
    │   ├─ 500~5000 → ✅
    │   └─ > 5000 → 豁免检查
    │                ├─ 价格带 ∩ [500,2000] ≠ ∅ → ✅ 豁免
    │                └─ 否则 → +「客单价偏高」
    │
    ├─ GPM ≥ 3000？
    │   └─ 否 → +「GPM低」
    │
    └─ 评语：
        ├─ 无问题 → 「✅ 优质」
        └─ 有问题 → 拼接所有标记
```

## 五、邀约决策

| 评语 | 动作 |
|------|------|
| ✅ 优质 | 进入邀约名单 |
| 有任何不通过标记 | 保持 PENDING，不主动邀约 |
| 客单价偏高（无豁免）| 保持 PENDING，等待人工判断是否手动发 |
| GPM低 | 保持 PENDING，不邀约 |

## 六、精准优先级（用户品类成交 + 过往开播频率）

> 原始筛选条件不变。此规则只改变「谁排在前面」，第一版不做一刀切硬淘汰。

### 6.1 为什么不用未来排播做主指标？

达人未来排播计划经常不完整，接口里看不到不代表达人未来不会播。因此「开播频率高」主要参考**过往开播频率**，未来直播计划只作为搜索入口和辅助信号。

### 6.2 新增优先级信号

| 优先级 | 信号 | 字段 | 用法 |
|---|---|---|---|
| P0 | 有{用户品类}成交记录 | `has_bag_sales` | 有真实箱包成交的达人优先 |
| P0 | {用户品类}成交额 | `bag_sales_amount` | 同样有{用户品类}成交时，销售额越高越优先 |
| P1 | {用户品类}成交均价 | `bag_avg_price` | 判断是否接近 你的品牌 价格带 |
| P1 | 过往开播天数 | `live_day_cnt` | 判断达人是否稳定开播 |
| P2 | 过往直播场次 | `live_count` | 辅助判断长期直播频率 |
| P2 | 合作商家数 | `partner_seller_count` | 判断商业化成熟度 |

### 6.3 推荐排序

候选达人按以下顺序排序：

1. 有{用户品类}成交记录
2. 过往开播天数高
3. {用户品类}成交额高
4. GPM 高
5. 下单粉丝率高
6. 粉丝数高

### 6.4 推荐等级

| 等级 | 条件 | 动作 |
|---|---|---|
| S | 有{用户品类}成交 + 过往高频开播 + 7维优质 | 优先进入确认清单 |
| A | 有{用户品类}成交 + 中高频开播 | 推荐邀约 |
| B | 无{用户品类}成交，但相关品类数据强 + 高频开播 | 可人工判断 |
| C | 数据一般或低频 | 暂不优先 |
