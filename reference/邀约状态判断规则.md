# 邀约状态判断规则

## 核心原则

顶层 `success=true` 只表示接口请求被平台处理，不代表创建了新邀约。

判断顺序：

1. 发送前读取达人权限详情。
2. 只有平台明确提示“已接受、已邀约、7天内不可重复、暂不接受”等情况时才跳过。
3. `permission_type` 单独出现时不能作为拦截依据。
4. 实际发送后，只有返回有效数字邀约编号才记为 `OK`。
5. 请求成功但无编号、也无明确跳过原因时记为 `VERIFY`。

## 状态定义

| 状态 | 定义 | 是否自动重试 |
|---|---|---|
| `OK` | 本次创建新邀约，并返回有效数字邀约编号 | 否 |
| `SKIP` | 本次未创建新邀约，平台明确已有邀约、已接受、重复限制或不可邀约 | 否 |
| `VERIFY` | 无新编号且平台原因不明确，需要人工或平台记录核验 | 否 |
| `DEFERRED` | 达到邀约标准，但因配额、网络或任务中断未完成 | 次日优先 |
| `PENDING` | 未达到自动邀约标准，人工观察 | 永不自动 |
| `READY` | 当次发送批次的临时状态 | 执行结束不得残留 |

## SKIP原因码

- `ALREADY_ACCEPTED`：达人已接受过本店直播邀约。
- `ALREADY_INVITED`：已有邀约或正在邀约流程。
- `RECENT_INVITE_RESTRICTED`：7天内不允许重复邀约。
- `NOT_ACCEPTING_OR_RESTRICTED`：达人不接受或平台限制。
- `HISTORICAL_MANUAL_FOLLOWUP`：已有微信、寄样或合作进度，不自动重邀。
- `HISTORICAL_SKIP_RESULT`：历史执行结果已明确跳过。

`SKIP`是“本次没有创建新邀约且不应自动重试”的总类，重复邀约只是其中一种。

## 证据保存

数据库额外保存：

- `status_reason`：机器可读原因码。
- `status_evidence`：平台提示、历史结果文件或人工跟进证据。
- `last_invite_attempt_at`：最后一次真实发送尝试时间。

已有邀约编号可作为证据保存，但状态仍可为 `SKIP`，表示本次尝试被跳过。
